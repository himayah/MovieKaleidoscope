# MovieKaleidoscope 仕様書

- 版: 0.4
- 日付: 2026-11-15
- 状態: CLI(M0〜M5)と GUI(第 2 段階)を実装済み

## 1. 概要

用意した動画素材を切り貼りして、サイケデリックな動画を自動生成するツール。生成 AI は使わない。入力動画からランダムに断片を切り出し、ランダムなエフェクトをかけ、連結して指定の長さの動画を出力する。BGM を指定した場合は、既定でその BPM に合わせてカットを切り替える。

- 第 1 段階: CLI だけで完結するツール
- 第 2 段階: GUI ラッパー(§17)

### 1.1 用語

| 用語 | 意味 |
|---|---|
| 断片 (clip) | 入力動画から切り出した 1 区間。最終的な動画の 1 カット分 |
| 計画 (plan) | どの動画のどこを、どの長さで、どのエフェクトで使うかを記述したタイムライン(JSON) |
| セグメント (segment) | 断片にエフェクトをかけて個別に書き出した中間ファイル |
| バックエンド | エフェクトを実行する方式。`ffmpeg`(フィルタ)と `frame`(Python でフレーム単位処理) |

### 1.2 スコープ

| 区分 | 内容 |
|---|---|
| 対象 | 入力収集・検証、BPM 解析、計画生成、エフェクト適用、連結、音声合成、CLI、設定ファイル、自動テスト |
| 対象外(v1) | 音声の加工、トランジション(ハードカットのみ)、エフェクトの重ね掛け(設計のみ対応)、途中再開、ハードウェアエンコード |

## 2. 全体アーキテクチャ

```
[入力収集/検証] → [BPM解析(任意)] → [Planner] → plan.json → [Renderer] → seg_*.mp4 → [Concat+Mux] → 出力
                                       乱数で決定            断片ごとに個別書き出し
```

- **Planner と Renderer を分離する。** Planner は乱数でタイムラインを作るだけで、映像は処理しない。Renderer は plan を受け取って映像を処理する。
- plan は常に JSON で保存する(既定は出力ファイルの隣に `<output>.plan.json`)。`--from-plan` で再レンダリングできる。
- core はライブラリとして `print` や `sys.exit` を行わず、進捗はコールバック、キャンセルはイベントで受ける。CLI は core の薄いラッパーにし、GUI も同じ API を呼ぶ。

```python
# 想定する公開 API
result = generate(config, progress=cb, cancel=event)   # 設定 → 出力まで一括
plan   = make_plan(config)                              # 計画だけ作る
result = render_plan(plan, config, progress=cb, cancel=event)
```

### 2.1 レンダリング方式(ハイブリッド)

断片 1 つにつき、次の流れで 1 つのセグメントファイルを作る。

```
ffmpeg(デコード: -ss/-t/loop → scale+crop → fps → [ffmpeg系エフェクト])
   ↓ rawvideo パイプ(frame系エフェクトがあるときのみ)
Python(numpy/OpenCV: frame系エフェクト)
   ↓ rawvideo パイプ
ffmpeg(エンコード: libx264 → seg_00001.mp4)
```

- frame 系エフェクトがない断片は、ffmpeg 1 プロセスだけで完結させる(高速)。
- エフェクトは「ffmpeg フィルタ文字列を返す」か「フレームを受けて返す」かのどちらかのバックエンドを持つ。
- 同じ効果でも、ffmpeg フィルタでパラメータの時間変化を表現できない場合は frame バックエンドを使う。どちらを使うかは実装時に確定する(§7 の想定は目安)。
- 将来の重ね掛けに備え、plan 上の断片のエフェクトは**リスト**で持つ。v1 の Planner は常に 1 要素のリストを作り、Renderer も 1 要素のみ扱う(複数要素の実行方法は将来設計する)。
- フィルタの適用順は、`setpts`(先頭を t=0 に)→ 時間軸のエフェクト(`speed`)→ `fps` → `scale`/`crop` → 画像のエフェクト(`reverse` を含む)→ `format`。`reverse` は、断片の長さちょうどのフレーム数に切ってから反転するため、`fps` の後(出力解像度)に置く。バッファするフレームが小さく済み、フレーム数も正確になる。`reverse` は入力を終端まで読むので、入力に `-t`(素材の長さ + 0.5 秒)の上限を付ける。

## 3. 入力

### 3.1 入力の指定

- `-i/--input` を複数回指定できる。ファイルでもフォルダでもよい(混在可)。
- フォルダは、既定では直下のみを対象とし、`--recursive` で再帰する。対象拡張子は設定で変更できる(既定: `mp4 mov mkv avi webm m4v mpg mpeg wmv flv`)。
- 入力の並び順は、`-i` の指定順。フォルダ内は自然順(名前順)。
- ファイルを直接指定した場合は、拡張子を問わず ffprobe で検査し、動画として読めれば採用する。拡張子フィルタはフォルダ探索にのみ適用する。
- 重複したパス(実体が同じもの)は 1 つにまとめる。

### 3.2 検証

- 全入力を ffprobe で検査する(全フレームのデコードはしない)。次のいずれかに当てはまるものは**警告を出してスキップ**する: ffprobe が失敗する、映像ストリームがない、長さまたはフレームレートが取得できない、長さが 0.5 秒未満。
- 有効な入力が 0 件ならエラー終了する(終了コード 3)。
- レンダリング中の失敗(ffmpeg の異常終了、またはセグメントのフレーム数が plan と一致しない)が起きた断片は、警告を出し、別の入力から同じ長さの断片を選び直して**1 回だけ**再試行する(`retry` 乱数ストリームを使う)。再試行も失敗したらエラー終了する(終了コード 1)。実際に使われた断片は、レンダリング完了後に plan へ書き戻す。
- `--from-plan` では選び直しをせず、失敗した時点でエラー終了する。

### 3.3 出力の解像度とFPS

- 既定値は**最初の有効な入力**(§3.1 の並び順)の解像度と FPS。`--width/--height/--fps` または設定で上書きできる。
- 既定の解像度は**最大 1080p**(長辺 1920、短辺 1080。縦長も同じ)とし、それより大きい入力はアスペクト比を保って縮小する。4K の入力から 4K の出力を作ると、3.4 分で 1.7 GB、生成中のメモリが 17 GB になったため(2026-11-16、C4・C5)。`--width/--height` で指定すれば 4K でも出力できる。
- FPS は ffprobe の `avg_frame_rate` を有理数のまま保持する(例: `30000/1001`)。取得できない、または 1〜120 の範囲外のときは 30 とする。
- 最初の入力から決めた FPS が標準の値(15、23.976、24、25、29.97、30、48、50、59.94、60、100、120。29.97 などは `30000/1001` のような正確な値)でなければ、**比が最も近い標準の値に丸める**(同じ近さなら低い方)。VFR の素材は `avg_frame_rate` が `3120/179`(約 17.43)のような半端な値になり、スマートフォンの動画は `2997003/100000` のようになるため(2026-11-16 に決定、TESTING.md の C6)。例: 17.43 → 15、29.97003 → 29.97。`--fps` や設定で指定した値は丸めない。
- `width` と `height` の一方だけを指定した場合は、最初の入力のアスペクト比を保って他方を決める。
- 解像度やアスペクト比が違う入力は、**拡大して全面を埋め、はみ出た部分をクロップ**する(`scale=increase` + `crop`)。
- 出力は `yuv420p` で、幅・高さは偶数に丸める。SAR は 1 に正規化する。
- 入力の FPS が違う場合や VFR の場合は、`fps` フィルタで出力 FPS に揃える。
- 回転メタデータは ffmpeg の自動回転に任せる。
- 10bit・HDR の入力は、トーンマッピングなしで 8bit に単純変換する(色味は変わりうる。対応対象外)。
- **色空間**: 出力は常に BT.709・limited range とし、全セグメントのタグ(`colorspace`、`color_primaries`、`color_trc`、`color_range`)を明示する。連結したファイルのタグは最初のセグメントのものになるため、全セグメントで一致させる必要がある。入力の YCbCr 行列は ffprobe のタグから判定し、タグがなければプレーヤーの慣習に従う(高さ 720 以上は BT.709、未満は BT.601)。判定結果は plan の `source.matrix` に記録する。BT.709 以外の素材は、ffmpeg の中で RGB を経由して BT.709 に変換する(swscale は YUV 同士の行列変換をしないため)。frame バックエンドでは、デコード時に素材の行列で RGB にし、エンコード時に BT.709 で YUV に戻す。行列を明示しないと、新しい ffmpeg(タグに従って変換する)と 4.4(無視する)で結果が変わる。
  - **すべての変換で行列を明示する**(Windows で実測、2026-11-15。4.4.1 と 6.1.1 では起きず、7.1.1 と 8.1.2 で起きる)。新しい ffmpeg はフィルタグラフ全体で色の属性をネゴシエーションするため、(1) 先頭の `scale` に `in_color_matrix` / `out_color_matrix` がないと、タグのない素材が BT.601 と見なされ、エンコーダの BT.709 のタグに合わせて変換されて色がずれた(4.4 では起きない)。(2) RGB でしか動かないフィルタ(`rgbashift`)の前後に ffmpeg が自動で入れる変換は、行列をフレームのタグから選ぶため、版によって片方向だけ行列が変わり色がずれた。`rgbashift` の前後は `scale=in_color_matrix=bt709:in_range=tv,format=gbrp` と `scale=out_color_matrix=bt709:out_range=tv` で明示的に変換する。
  - **タグはフレームにも付ける**(`setparams=range=tv:color_primaries=bt709:color_trc=bt709:colorspace=bt709` をフィルタの最後に置く)。ffmpeg 7.1.1 以降(8.1.2 でも)は、フレームの属性が「未指定」だとエンコーダの `-color_primaries` / `-color_trc` を無視し、出力にタグが付かなかった(4.4 と 6.1.1 はエンコーダのオプションを使う)。両方を指定すれば、どの版でも付く。

## 4. 音声と BPM

### 4.1 音声の扱い

| 指定 | 動作 |
|---|---|
| `--audio FILE` | 指定ファイルを出力に合成する。AAC 192kbps |
| 指定なし(既定) | 音声なしの出力。`--no-audio` でも明示できる |

- 入力動画の音声は使わず、断片では常に破棄する。
- 音声の加工(エフェクト・フェードなど)は行わない。
- `audio.start`(秒)で、音声の途中から使い始められる。
- 音声が出力長より長い場合は、出力長で切り詰める。短い場合は、残りを無音で埋めて警告を出す(拍のグリッドは音声の終了後も延長する)。
- `--audio` で指定したファイルが読めない、または音声ストリームがない場合は、エラー終了する(終了コード 2)。入力動画と違い、スキップはしない。

### 4.2 出力長

- `--duration`(秒、または `mm:ss`)で指定する。
- 未指定で音声がある場合は、音声の長さ(`audio.start` を引いた値)を出力長とする。
- 未指定で音声もない場合はエラー(終了コード 2)。

### 4.3 BPM 解析

- BPM が必要なのは `beat` 方式のときだけ。`--bpm` の指定があれば解析せず、なければ音声を解析する。
- 音声がなくても `--bpm` を指定すれば `beat` 方式で動く(音声なしの動画になる)。音声も `--bpm` もない状態では、`auto` は `fixed` になり、`beat` を明示した場合はエラー(終了コード 2)。
- 解析した BPM と、最初の拍の時刻(`offset`)をログに出し、plan にも記録する。`offset` は動画の 0 秒(= `audio.start` の位置)を基準とし、0 以上 1 拍未満に正規化する。
- `offset` は `audio.beat_offset` で手動指定できる。`--bpm` を手動指定して `beat_offset` を省略した場合は、`offset = 0`(音声の先頭を拍の頭とみなす)とする。
- `audio.bpm_range`(既定 `[70, 180]`)の外のテンポは、範囲内に倍・半にして扱う(手動指定の値には適用しない)。ただし 87 と 174 のように、範囲内に 2 通りの読み方がある曲(どちらも拍に乗る)は、どちらになるか決まらない。別の方が欲しいときは `--bpm` で指定する。
- 解析に失敗した場合、`auto` では警告を出して `fixed` 方式にフォールバックする。`cut.mode: beat` を明示している場合はエラー終了する(終了コード 1)。どちらの場合も、`--bpm` で回避できる旨を表示する。失敗とみなすのは、無音、周期性がない(ノイズや、拍のない音)、音声が短すぎる(解析に使える部分が 15 秒未満)、デコードできない、の場合である。
- 実装は `BpmDetector` インターフェースの背後に置く。テンポ一定の曲を前提とし、テンポ変化には対応しない。

**検出方法**(`audio/bpm.py`。numpy のみで、librosa などの依存はない):

- 音声は ffmpeg で 22050Hz モノラルにデコードし、対数スペクトルフラックスから onset の強さを求める。これを候補のテンポの周期で折りたたみ、onset が最も 1 つの位相に集中するテンポを BPM とする(0.05 BPM 刻みで探索し、0.002 BPM まで絞り込む)。位相は、その集中の偏角(連続値)から求める。
- 「全帯域」と「200Hz 以下(キック・ベース)」の 2 つの onset 強度を試し、周期性が強い方を採用する。全帯域だけだと、裏拍のハイハットを拍と取り違える。
- 周期性が偶然のものでないことを、onset 強度を短いブロック単位でシャッフルした場合の最大値(偶然の水準)と比べて確かめる。実際のピークが偶然の水準の 1.7 倍未満なら、拍なしとする。短い窓では、数千通りのテンポ候補のどれかが、ノイズでも偶然に揃うためである。
- 範囲を超える速いテンポ(例: 300 BPM)は、範囲内に周期性が見つからなかった場合のフォールバックとして、範囲の 2 倍まで探索し、見つかったテンポを半分に畳む。常に 2 倍まで探索すると、通常の曲の 8 分音符のグリッドが選ばれてしまう。
- 検出位置には窓の幾何に由来する約 16ms の遅れ(onset の見た目の位置が実際より前)があるため、これを補正する(合成したクリック音とキック音で較正した値)。
- 解析範囲は、出力の長さではなく、`audio.start` からの音楽そのもの(最大 300 秒)とする。窓が長いほどテンポは信頼でき、精度も上がる(不確かさは窓の長さにほぼ反比例し、拍のグリッドは動画全体へ外挿されるため)。
- 解析は 1 回の実行につき 1 回だけ行う。300 秒の解析に約 1 秒。

**実測**(合成した音声。クリック、キック+スネア+裏拍ハイハット、タイミングのジッタ、ノイズ床):

| 条件 | 結果 |
|---|---|
| 120 秒、ジッタなし | テンポの誤差 0.01 BPM 未満、offset の誤差 1ms 未満 |
| 300 秒、ジッタ 4ms | テンポの誤差 0.001 BPM、offset の誤差 1.5ms |
| 15 秒、ジッタ 6ms | テンポの誤差 約 1 BPM(窓が短いほど大きくなる) |
| ランダムなノイズ(15〜60 秒、各 12〜30 通り) | すべて拍なしと判定 |

(参考: librosa の `beat_track` は、同じ正確なクリック音で、120 BPM を 117.45、140 BPM を 143.6、128.3 BPM を 129.2 と推定した。2% の誤差は 2 分で約 2.4 秒のずれになるため、採用しなかった。)

## 5. 断片の切り出しと計画

### 5.1 カット方式 (`cut.mode`)

| mode | 断片の長さ | 備考 |
|---|---|---|
| `auto`(既定) | 音声または `--bpm` の指定あり → `beat`、なし → `fixed` | |
| `fixed` | 固定秒数(既定 2.0 秒) | |
| `random` | `[min, max]` 秒の一様乱数(既定 1.0〜4.0) | |
| `beat` | 拍数 × (60 / BPM) | 拍数は `beats` のリストから断片ごとにランダムに選ぶ(要素 1 つなら固定。既定 `[4]`) |

- 音声が指定されていても、`mode` を `fixed` または `random` にすれば、音声(BPM)を無視してカットできる。
- `beat` 方式の境界は、拍のグリッド上に置く。`b_0 = offset`、`b_{j+1} = b_j + n_j × (60/BPM)`(`n_j` は `beats` から選んだ拍数)とし、断片 j は `[b_j, b_{j+1})` とする。
- 導入部 `[0, b_0)` は、長さが 1/4 拍以上で、かつ 4 フレーム以上なら独立した断片とし、そうでなければ最初の断片に含める(`[0, b_1)`)。
- 全方式で、境界時刻を累積し、`round(t × fps)` の差を各断片のフレーム数とする。**断片の長さを個別に丸めて足すのではなく、境界時刻から求める。** 誤差が蓄積しないようにするためである。
- 最後の断片が 4 フレーム未満になる場合は、直前の断片に含める(ffmpeg の起動を無駄にしないため)。

### 5.2 素材の選び方

- **入力の選択は均等にする。** シャッフルバッグ方式で、全入力を 1 巡するまで重複なく選び、1 巡したら再シャッフルする。
- 切り出し位置は完全ランダムで、断片同士の重複や再利用を許す。
  - 入力の長さが必要な長さ以上なら、`in` を `[0, 長さ − 必要長]` の一様乱数とする。
  - 入力が必要な長さに満たなければ、`in = 0` で**ループ再生**して嵩増しする(plan に `loop: true` を記録)。
- 速度変化(§7 `speed`)がかかる断片では、必要長を「出力長 × 平均速度」として扱う(`ramp` は出力時間に対して線形に変化するので、平均速度は始点と終点の算術平均で厳密に求まる)。エフェクトは素材より先に決め、素材の位置はクリップごとの乱数(`in:<番号>`)で決める。ループの有無やエフェクトの違いが、他のクリップの選択に影響しないようにするためである。
- 目標長に達したら終了する。**最後の断片は計画段階で残りフレーム数に切り詰める**(再エンコードで切らない)。

### 5.3 再現性

- `seed` を設定または `--seed` で指定する。未指定なら生成して、ログと plan に記録する。
- 乱数は用途別のストリームに分け、それぞれ `seed` から派生させる: `cut`(断片の長さ・拍数)、`source`(入力の選択・切り出し位置)、`effect`(エフェクトの選択とパラメータ)、`retry`(§3.2 の再試行)。エフェクトの設定を変えても、カットと素材の選択が変わらないようにするためである。
- 同じ seed・入力・設定・バージョンなら、同じ plan ができる(映像のピクセル完全一致は ffmpeg のバージョンに依存し、保証しない)。

### 5.4 plan のスキーマ(抜粋)

```json
{
  "version": 1,
  "seed": 123456,
  "output": {"width": 1280, "height": 720, "fps": "30/1", "duration": 60.0, "frames": 1800},
  "audio": {"path": "/abs/path/bgm.wav", "start": 0.0, "bpm": 128.0, "beat_offset": 0.21},
  "clips": [
    {
      "index": 0,
      "start_frame": 0, "frames": 54,
      "source": {"path": "/abs/path/a.mp4", "in": 12.34, "span": 1.8, "loop": false},
      "effects": [
        {"type": "rgbshift",
         "params": {"dx": {"motion": "sine", "base": 6, "amp": 4, "period": 2, "unit": "beat", "phase": 0.3}}}
      ]
    }
  ]
}
```

- 連続パラメータの動きは、plan 内で完全に解決した値(motion の種類と係数)で保持する。レンダリング時に乱数を使わない。
- パスは絶対パスで保存する。fps は有理数の文字列。時間量(モーションの周期など)は `unit`(`beat` または `sec`)を持つ。

## 6. パラメータのモーション

連続値パラメータは、断片内で時間変化させる。パラメータごとにランダムな範囲を持ち、断片ごとに motion の種類と係数をランダムに決める。

| motion | 内容 |
|---|---|
| `const` | 一定値 |
| `ramp` | 開始値 → 終了値へ線形に変化 |
| `sine` | `base + amp × sin(2π(t/period) + phase)`。period は秒、または拍(BPM が分かるとき) |
| `pulse` | 拍の頭で最大値、拍の間で指数的に減衰(BPM が分かるときのみ。BPM がなければ `sine` に置き換える) |

- motion の種類は、そのパラメータが許すもの(エフェクトごとに宣言)から一様な確率で選ぶ。
- パラメータ値の範囲の既定値は各エフェクトの実装に持たせ、目視で調整する(本仕様では数値を固定しない。`--list-effects` で確認でき、設定ファイルで上書きできる)。
- 拍単位(`unit: beat`)の指定は、BPM が分かるときだけ使う。BPM がないときは、Planner が秒単位に換算して plan に書く(`pulse` は `sine` に置き換える)。
- 離散パラメータ(ミラー方向、万華鏡の分割数など)は断片内で固定する。ただし `alternate_beats` のように、切り替え間隔を持つものは例外とする。
- 断片の先頭は拍の境界に揃っているため、断片ローカルの時間 `t` から拍位相を計算できる。
- エフェクトごとのパラメータ範囲、有効/無効、出現の重みは、設定ファイルで上書きできる(§9)。

## 7. エフェクト

全 15 種のエフェクトを v1 に含める。1 断片につき 1 つを、重みつきでランダムに選ぶ(エフェクトなしの断片は作らない)。

| 名前 | 内容 | 主なパラメータ(動くものに ★) | 想定バックエンド |
|---|---|---|---|
| `flip` | 上下/左右/両方の幾何反転。一定間隔で反転と元を交互に切り替えることもある | axis、alternate(周期) | ffmpeg(`hflip`/`vflip` の `enable` 式で交互切り替え) |
| `negate` | 色反転(ネガポジ) | ★mix(0〜1。0 で元の色、1 で完全な反転。元と反転を半々に混ぜると一様な灰色になるため、0.2〜0.8 は使わず瞬時に切り替える(2026-11-16)) | frame |
| `mirror` | 片側を反対側に鏡写し(左→右、右→左、上→下、下→上、四分割) | mode、★pos(軸の位置。0.3〜0.7) | frame |
| `solarize` | しきい値以上を反転 | ★threshold(60〜200)、channels(rgb、r、g、b、rg、rb、gb のいずれか) | frame |
| `rgbshift` | R と B を逆方向にずらす(G は動かさない) | ★amount(px)、angle(方向) | ffmpeg(amount が一定のとき。整数ピクセル)/ frame(動くとき。サブピクセル) |
| `hue` | 色相回転 | ★回転速度(度/秒)、開始角 | ffmpeg |
| `saturate` | 彩度ブースト | ★gain(1.5〜4) | ffmpeg |
| `posterize` | 階調を減らす | ★levels(2〜8。時間変化は四捨五入して適用) | frame |
| `speed` | 早送り/スロー(0.25〜4 倍) | ★rate(`const` または `ramp` で加減速。範囲は対数一様) | ffmpeg(`setpts` の式) |
| `reverse` | 逆再生 | なし(下記の制限あり) | ffmpeg |
| `zoom` | 拡大縮小(中心移動つき)。縮小時は端を折り返して埋める | ★scale(0.5〜2.5)、★cx、★cy | frame |
| `kaleidoscope` | 万華鏡(極座標の折り返し) | segments(3〜12。断片内で固定)、★angle(回転角)、★cx、★cy | frame |
| `strobe` | 黒/白/反転のフラッシュ | mode、★rate(const か ramp)、unit(`hz` または `beat`)、duty。`beat` は「1 拍あたりの点滅回数」(0.5、1、2、4 のいずれか)で、BPM があるときだけ選ばれる | frame |
| `feedback` | 直前の出力を拡大・回転・減衰させて残像として重ねる | ★decay、★zoom(1 フレームごとの拡大率)、★rot(1 フレームごとの回転)。断片ごとに状態をリセット | frame(状態あり) |
| `tile` | 画像を縮小して上下左右に繋ぎ(タイリング)、平面上でスクロール/回転させる | transform、tile_n(2〜6)、wrap、scroll_angle、★speed(タイル/秒。const か ramp)、★angle(回転角。画面中心まわり) | frame |

`tile` の詳細:

- 画面に縦横 `tile_n` 枚(2〜6、非整数可)のタイルが見えるように画像を繋いだ無限平面を作り、その上でカメラを動かす。
- `transform` は断片ごとにランダムに選ぶ。`none`(タイリングのみ)、`scroll`、`rotate`、`scroll+rotate` の 4 通りで、「それらの組み合わせ」はこの中で表現する(汎用の重ね掛けは v1 の対象外)。
- `wrap` は `repeat`(そのまま繰り返す)と `mirror`(隣を鏡像にして繋ぎ目を目立たせない)から選ぶ。
- スクロールは任意の方向に動かす。BPM があるときは、「N 拍(1、2、4、8)でちょうど 1 タイル分」の速度(`scroll_beats`。ループが自然に繋がる)も選ばれる。
- 回転は画面中心まわりで、角度は連続して変化する(ramp で回り続け、sine で揺れる)。BPM があるときは、N 拍(1、2、4)ごとに 90° ずつ回る離散回転(`rotate_beats`、`rotate_dir`)も選ばれる。回転の中心は動かさない。
- 実装は OpenCV の `remap`(`BORDER_WRAP` / `BORDER_REFLECT`)で行い、写像テーブルは断片内で使い回す。

注意点:

- `flip`(幾何反転)と `negate`(色反転)は別のエフェクトとして扱う。
- `reverse` は断片をバッファするため、メモリ使用量が増える。断片の長さの上限(既定 10 秒。`effects.params.reverse.max_sec`)を設け、超える断片では `reverse` を候補から外す。
- `speed` の速度が速い断片は、必要な素材長が長くなる(§5.2)。
- エフェクトのパラメータ範囲の既定値は各エフェクトの実装にあり、`--list-effects` で確認できる。上書きは `effects.params.<名前>.<パラメータ>: {min, max}`(オプション値は `reverse: {max_sec: 8}` の形式)。名前やキーの誤りはエラーにする。
- `feedback` は断片ごとに状態をリセットする。
- `frame` 系エフェクトは、`frame_processor(params, ctx)` で断片ごとに `process(frame, t, n) -> frame` を返す形で実装する(`frame` は 8bit RGB の `H×W×3`、`t` は断片の先頭からの秒、`n` はフレーム番号、`ctx` に解像度・FPS・BPM・断片長を持つ)。入力の配列を書き換えてはならない。状態(`feedback`)は processor の中に持つ。`ffmpeg` 系エフェクトは、`pre_filters` / `post_filters` でフィルタ文字列のリストを返す。同じエフェクトが、パラメータによってバックエンドを切り替えてもよい(`backend_for`。`rgbshift` が該当)。
- エフェクトの実装はパラメータの検証を兼ねる: plan の読み込み時に processor / フィルタを構築して確かめるため、構築は軽くしておく(大きな配列は初回の呼び出しまで作らず、解像度ごとに共有する)。
- エフェクトはレジストリに登録する方式にして、追加時に既存コードを変更しなくて済むようにする。

## 8. 出力

### 8.1 セグメント

- 断片ごとに、作業ディレクトリへ `seg_00001.mp4` の名前で個別に書き出す。
- 全セグメントで、コーデック・解像度・FPS・ピクセルフォーマット・GOP を揃える。連結時に再エンコードしないためである。
- 書き出し後、各セグメントのフレーム数(ffprobe の `nb_frames`。コンテナのヘッダから読むだけで、デコードしない)が plan と一致することを確認する。不一致は §3.2 の失敗として扱う。
- 並列度は `jobs`(既定 `auto` = CPU コア数の半分、最小 1)で指定する。`auto` のときは、さらに**空きメモリの 70% に収まる数**まで減らす。1 つあたりの見積もりは「100 MB + 最大の入力の画素数 × 170 バイト」(4K の入力で約 1.5 GB。実測: 4K で 1 つあたり約 1.4 GB、720p で約 0.17 GB)、`reverse` を含む plan では、最長の断片を出力の解像度で溜める分を加える。減らしたときはログに出す(2026-11-16、C5)。各 ffmpeg のスレッド数は `CPU コア数 / jobs` を目安に配分し、過剰に競合させない。

### 8.2 連結と合成

- ffmpeg の concat デマクサ(`-c copy`)で連結し、同じコマンドで音声を合成する(`-c:v copy -c:a aac`、音声は `-t` で出力長に切る)。
- 連結リストには、各ファイルの `duration` を plan から計算して明記する。MP4 のヘッダはセグメントの長さをミリ秒単位で持つため、これに頼ると継ぎ目ごとに丸め誤差(約 0.3ms)が蓄積し、数百カットで音楽とずれる(M1 で実測)。`duration` は累積時刻(マイクロ秒に丸め)の差から求め、誤差が蓄積しないようにする。
- 各セグメントは、フィルタの先頭で `setpts=PTS-STARTPTS` を適用し、最初のフレームを正確に t=0 に置く。シーク位置が入力のフレーム境界とずれていると、`fps` フィルタが最初のフレームを次のスロットへ丸め、先頭に 1 フレーム分の空きができて、連結時にカットごとのコマ飛びになる(M1 で実測)。セグメントは B フレームなし(`-bf 0`)で書き出す(連結のタイミングが ffmpeg のバージョンに左右されないようにする安全策)。
- セグメント(と frame 系のデコード)には、出力の FPS を `-r` で明示する。`fps` フィルタで全フレームは出力の格子に乗っているが、出力側の CFR の処理はフィルタグラフが伝えるフレームレートを使う。ffmpeg 7.0.2 では `reverse` の後でこれが失われ、25 fps と見なされて 30 fps の断片の 6 枚に 1 枚が捨てられた(60 → 51。CI の Linux で発見、2026-11-16)。
- `-movflags +faststart` を付ける。
- 連結リストは、作業ディレクトリ内の相対パス(ASCII のみ)で書く。日本語パスの問題を避けるためである。
- 連結後の長さが plan と 1 フレーム以上ずれた場合は警告を出す(ffprobe の duration で比較し、全デコードはしない)。

### 8.3 エンコード設定

| 項目 | 既定 |
|---|---|
| コンテナ | mp4 |
| 映像 | H.264。`video.backend: auto`(既定)が起動時に GPU の NVENC を使えるか確認し、使えれば `h264_nvenc`、使えなければ `libx264` を使う(§8.3.1)。`crf: 18`(nvenc では `-cq` に、同じ 0–51 スケールで渡る)、`preset: medium`(software のみ。nvenc 側のプリセットは固定で `p5`)、`yuv420p` |
| 音声 | AAC 192kbps(音声ありの場合) |

#### 8.3.1 GPU エンコード(NVENC)(GPU redesign §A、2026-11-22)

- `video.backend`: `auto`(既定) / `software` / `nvenc`。`auto` は ffmpeg の `-encoders` 一覧に `h264_nvenc` があるか見たあと、256×256 の短いダミー映像を実際に nvenc でエンコードしてみて判定する(ffmpeg のパスごとに結果をキャッシュし、プロセス内で 1 回だけ実機確認する)。
- 並列数の既定(`jobs: auto`)は、nvenc かつ plan が Python フレームバックエンド(§7、エフェクトの `backend_for` が `"frame"` を返すもの)を使わないときだけ**論理コア数の 3/4**。それ以外(software、またはフレームバックエンド併用時)は**論理コア数の半分**のまま(`pipeline.default_jobs()`)。nvenc は libx264 ほど CPU コアを使わないため、より多くのジョブを同時に走らせられる想定だが、フレームバックエンドの per-frame 処理は GIL を握るため、その場合は増やしても速くならない(review finding, 2026-11-21)。
- GPU のドライバは同時に開ける NVENC セッション数に上限があり、機種・ドライバ依存で事前に知る方法がない。実測(2026-11-22、24 論理コア・コンシューマ GPU 1 枚): 上記の既定(18 ジョブ)では `h264_nvenc` が `Could not open encoder before EOF` を返し、**レンダリング全体が失敗**した。10 ジョブでは成功、14 ジョブでは失敗(この機種の上限は 10〜13 ジョブの間)。
- そのため、NVENC のエンコーダを開けなかった場合(エラー文言に `nvenc` と `Could not open encoder` / `Generic error in an external library` のいずれかを含む)は、そのクリップをその場で再試行しつつ、同時に NVENC セッションを開けるクリップ数の上限を 1 ずつ下げる(`pipeline._NvencGate`。この render 1 回の間だけ有効で、プロセス間・呼び出し間で共有しない)。上限が 1 まで下がってもなお失敗する場合は、GPU・ドライバ側の別の問題とみなしてエラーを返す。
- software 入力の読み出し用に別で予約していたエンコーダ固有の `-threads` は、nvenc では意味を持たないため渡さない。

### 8.4 作業ディレクトリ

- 既定は OS の一時ディレクトリ配下に専用フォルダを作る。`--work-dir` で変更できる。
- Windows では、既定の一時ディレクトリのドライブの空き容量が 20GB 未満のとき、ローカルの固定ドライブのうち空き容量が最大のものに切り替える(GPU redesign §D、2026-11-22)。セグメントファイル一式がまとまった容量を使うための安全策で、速度目的の最適化ではない。ドライブの判定はプロセス単位でキャッシュする(ドライブ構成は実行中に変わらない前提)。POSIX ではドライブレター概念がないため常に通常の OS 一時ディレクトリを使う。
- 正常終了時、失敗時、Ctrl+C 時のいずれでも削除する。`--keep-temp` で残せる。
- Ctrl+C では、起動中の ffmpeg 子プロセスを終了させてから後始末する(終了コード 130)。
- 削除に失敗したら警告を出す(以前は黙って無視していたため、キャンセル後も生き残った ffmpeg がセグメントを開いたままにしていることに気づけなかった。§11)。

### 8.5 電源プラン(Windows)

- レンダリング中だけ Windows の電源プランを「高パフォーマンス」に切り替え、終了時(正常終了・失敗・中断を含む)に元のプランへ戻す(`util/power.py`)。CPU/GPU 負荷の高い処理が既定の「バランス」プランでクロックを抑えられるのを避けるための最適化。
- `powercfg` が使えない、非 Windows、プランの取得・切り替えに失敗した場合は警告を出すだけでレンダリングは続行する(ベストエフォートで、失敗させない)。
- `runtime.power_plan: false` で無効化できる(既定は `true`)。

## 9. 設定ファイル

形式は YAML(PyYAML)。UTF-8。CLI オプションは設定ファイルより優先する。優先順位は **CLI > 設定ファイル > 既定値**。未知のキーはエラーにする(typo の検出)。

- 設定ファイル内の相対パスは設定ファイルのあるディレクトリ基準、CLI で指定した相対パスはカレントディレクトリ基準で解決する。
- リスト型の項目(`inputs`、`effects.enabled` など)を CLI で指定した場合は、設定ファイルの値を置き換える(追加ではない)。

```yaml
# config.example.yaml
inputs:
  - ./clips
  - ./extra/one.mp4
recursive: false
extensions: [mp4, mov, mkv, avi, webm, m4v, mpg, mpeg, wmv, flv]   # フォルダ探索のみ
output: ./out/result.mp4
plan: null            # null なら <output>.plan.json
duration: 60          # 秒。省略時は音声の長さ
seed: null            # null なら自動生成して記録
overwrite: false      # CLI の -y と同じ

video:
  width: null         # null なら最初の入力に合わせる
  height: null
  fps: null
  crf: 18
  preset: medium
  backend: auto       # auto / software / nvenc(§8.3.1)

audio:
  file: ./bgm.wav     # null なら音声なし
  start: 0.0
  bpm: null           # null なら自動解析
  beat_offset: null
  bpm_range: [70, 180]

cut:
  mode: auto          # auto / fixed / random / beat
  fixed: 2.0
  random: {min: 1.0, max: 4.0}
  beats: [4]          # beat モード。複数ならランダムに選ぶ

effects:
  enabled: all        # または名前のリスト
  exclude: []         # 使わないエフェクト
  weights: {speed: 2.0, flip: 0.5}
  params:             # パラメータ範囲の上書き
    rgbshift: {amount: {min: 2, max: 20}}
    reverse: {max_sec: 10}

runtime:
  jobs: auto
  work_dir: null
  keep_temp: false
  ffmpeg: null        # null なら 環境変数 FFMPEG_BIN → PATH の順に探す
  ffprobe: null
  power_plan: true    # レンダリング中だけ Windows を「高パフォーマンス」に切り替える(§8.5)
```

## 10. CLI

コマンド名(案): `mkaleido`。

```
mkaleido [-c CONFIG] [-i INPUT ...] [-o OUTPUT] [options]
```

| オプション | 内容 |
|---|---|
| `-c, --config FILE` | 設定ファイル |
| `-i, --input PATH` | 入力ファイルまたはフォルダ(複数指定可) |
| `--recursive` | フォルダを再帰的に探索 |
| `-o, --output FILE` | 出力ファイル |
| `-d, --duration T` | 出力長(秒 または `mm:ss`) |
| `--audio FILE` / `--no-audio` | 音声ファイル / 音声なし |
| `--bpm N` | BPM を手動指定 |
| `--cut-mode M` | `auto` `fixed` `random` `beat` |
| `--cut-length SEC` / `--cut-random MIN:MAX` / `--beats N[,N...]` | 断片の長さの指定 |
| `--width N --height N --fps N` | 出力形式の上書き |
| `--effects NAME,...` / `--exclude-effects NAME,...` | 使うエフェクトの絞り込み |
| `--seed N` | 乱数シード |
| `--plan FILE` | plan の保存先(既定 `<output>.plan.json`) |
| `--plan-only` | plan だけ出力して終了(映像・音声は処理しない) |
| `--from-plan FILE` | plan から再レンダリング |
| `--list-effects` | エフェクトとパラメータ範囲の一覧 |
| `--jobs N` / `--work-dir DIR` / `--keep-temp` | 実行設定 |
| `--ffmpeg PATH` / `--ffprobe PATH` | 実行ファイルの指定 |
| `-y, --overwrite` | 出力の上書き許可(既定は存在すればエラー) |
| `-q, -v` | ログの量 |
| `--dump-config` | 解決後の設定を表示 |

挙動の規則:

- 出力先(`-o` または設定の `output`)は必須。拡張子は `.mp4` のみ(それ以外はエラー、終了コード 2)。出力ファイルまたは plan が既に存在する場合は、`-y` がなければエラーにする。
- 断片の長さのオプションは `cut.mode` を暗黙に決める: `--cut-length` → `fixed`、`--cut-random` → `random`、`--beats` → `beat`。複数を同時に指定した場合や、`--cut-mode` と矛盾する場合はエラーにする。
- `--from-plan` では、解像度・FPS・カット・素材・エフェクト・音声・seed は plan の内容を使う。これらを CLI で指定した場合はエラーにし、設定ファイルの値は無視する。変更できるのは、出力先、エンコード設定(`crf`、`preset`)、実行設定(`jobs` など)、`-y`、`-q/-v` のみ。plan 内の入力ファイルが見つからない場合はエラー終了する(終了コード 3)。

終了コード: `0` 正常、`1` 実行時エラー、`2` 引数・設定エラー、`3` 有効な入力なし、`4` ffmpeg が見つからない、`130` 中断。

想定外の失敗の扱い:

- ファイル操作の失敗(出力先に書けない、ディスクが一杯、など)は、メッセージを出して終了コード 1 とする(トレースバックは `-v` のときだけ)。
- 想定していない例外も、「予期しないエラー: 型名: 内容」を出して終了コード 1 とする(`-v` で詳細)。
- 出力先がフォルダのときは、終了コード 2。
- `--from-plan` では、plan が参照する入力動画がなければ終了コード 3、音声ファイルがなければ終了コード 2(レンダリングを始める前に確認する)。

### 10.1 進捗表示

- 段階は「入力検証(ファイル数)→ BPM 解析 → 計画 → セグメント生成(**フレーム数**)→ 連結」。セグメントは長さがまちまちなので、クリップ数ではなくフレーム数で進捗を出す。
- 端末(TTY)では tqdm のバーを標準エラー出力に表示する。リダイレクトされているときは、バーの代わりに、段階の開始・25% ごと・完了をログに出す(`LogProgress`)。`-q` で、どちらも出さない。
- core は `ProgressCallback(stage, current, total)` を呼ぶだけにして、GUI でも同じ仕組みで使えるようにする(`util/progress.py` に共通部分がある)。

## 11. 実行環境とクロスプラットフォーム

- 第一ターゲットは **Windows ネイティブ**。将来 Linux / macOS でも動かす。
- Python 3.10 以上。依存: `numpy`、`opencv-python-headless`、`PyYAML`、`tqdm`。開発用: `pytest`。
- frame 系エフェクトのパイプの形式は、8bit の `rgb24`(高さ×幅×3 の numpy 配列)とする。
- ffmpeg / ffprobe は別途インストールする前提とする。探索順は、設定/CLI → 環境変数 `FFMPEG_BIN` / `FFPROBE_BIN` → `PATH`。見つからなければ、導入方法を添えてエラーにする。起動時にバージョンを確認する。最低バージョンは 4.4(動作確認済みの最古のバージョン。M2 以降で使うフィルタが判明した時点で見直す)。git ビルドなどでバージョンを判別できない場合は、警告を出して続行する。
- OS 依存を避ける規約:
  - パスは `pathlib` で扱い、文字列連結しない。
  - `subprocess` は引数リストで呼び、`shell=True` は使わない。
  - 設定・plan・ログは UTF-8 で読み書きする。
  - ファイル名やフォルダ名に日本語・空白が含まれても動くこと(テストに含める)。
  - 実行ファイル名は `shutil.which` で解決する(`.exe` を直書きしない)。
  - 子プロセスの終了処理は `terminate()` → `kill()` の順で、Windows でも同じコードで動くようにする。ただし **Windows ではプロセスツリーごと終了する**(`taskkill /PID <pid> /T /F`)。PATH 上の ffmpeg がランチャーのことがあるため(Chocolatey の `ffmpeg` パッケージは `C:\ProgramData\chocolatey\bin\ffmpeg.exe` というシムを置き、本物の ffmpeg.exe を子プロセスとして起動する)。`terminate()` はシムしか止めず、本物の ffmpeg がキャンセル後も動き続け、セグメントを開いたままにした(作業フォルダが消えない。2026-11-15 に Windows で実測)。
  - **Windows では、ffmpeg を別のプロセスグループで起動する**(`CREATE_NEW_PROCESS_GROUP`)。コンソールの Ctrl+C は同じコンソールの全プロセスに届くため、ffmpeg が先に異常終了し、メインスレッドが KeyboardInterrupt を受け取る前に、ワーカーがそれを「クリップの失敗」と見なして警告を出し、別の入力で再試行していた(終了コードは 130 だったが、誤解を招く警告と、再試行の ffmpeg が残った)。別のグループにすると Ctrl+C を受けるのは Python だけになり、子プロセスはこちらで止める。パイプ越しに ffmpeg を動かしているときは、**先に自分側のパイプを閉じてから**終了させる(書き込みでブロックしているデコーダは、SIGTERM に応じない。順序を逆にすると、キャンセルや失敗の後始末に 5〜10 秒かかった)。
  - 標準出力・標準エラーは、起動時に `errors="replace"` にする。日本語 Windows でリダイレクトした出力は cp932 になり、符号化できない文字で `print` やログが失敗するため(ファイル名や ffmpeg のメッセージなど、動的な文字列にも備える)。
  - ソース中のメッセージは、cp932 で符号化できる文字に限る(`—`(U+2014)などは使わない)。テストが検査している。
- 開発は現在の WSL2 上でも行える(ffmpeg 4.4.2、Python 3.10 が導入済み)。ただし `/mnt/c` 配下の動画は I/O が遅いので、パフォーマンスの評価は Windows ネイティブで行う。

## 14. リスクと対応方針

| リスク | 対応 |
|---|---|
| `concat -c copy` でタイムスタンプがずれる | M1 で実際に 2 種類のずれが発生し、対策済み(§8.2)。結合テストで全フレームの時刻の間隔と、末尾のずれ(0.5ms 未満)を検証している。Windows の新しい ffmpeg でも同じテストで確認する |
| frame バックエンドが遅い(Python のパイプ経由) | OpenCV の `remap` 等で書き、写像テーブルは断片内で使い回す。`jobs` で並列化する。実測して目標を決める |
| `reverse` のメモリ消費 | 断片長の上限を設ける(§7) |
| ffmpeg フィルタのパラメータ時間変化の限界 | 表現できないものは frame バックエンドへ。バックエンドの選択はエフェクトごとに差し替え可能にする |
| BPM 検出の精度(librosa の `beat_track` はテンポが 2〜3% ずれた) | numpy による自前の検出に変更(§4.3)。精度は上記のとおり。`BpmDetector` は差し替え可能 |
| 断片数が多い(1 拍カットなど)と ffmpeg の起動回数が増える。Windows ではプロセス起動のオーバーヘッドが効く | `jobs` で並列化する。M5 で数百断片の場合の所要時間を計測し、問題なら複数断片を 1 プロセスにまとめる方式を検討する |
| 倍テンポ・半テンポの取り違え(87 と 174 など。本質的に曖昧) | `bpm_range` と、120 付近を好む弱い事前分布。別の方が欲しいときは `--bpm` |
| 2 分を超える曲で、わずかなテンポ誤差が外挿で蓄積する | 窓を最大 300 秒に。テンポが一定でない曲(生演奏)は対象外。`--bpm`(小数可)で精密に指定できる |
| ffmpeg のバージョン差 | 起動時にバージョンを確認し、使用フィルタが無ければ分かりやすいエラーにする |
| Windows のパス・文字コード問題 | §11 の規約とテストで担保する |

性能目標: 720p / 30fps / 60 秒の出力を、frame 系エフェクトを含む既定設定で、一般的な PC(`jobs=auto`)で 5 分以内に生成する。WSL2・Windows ネイティブとも余裕で満たしている(README の「性能の目安」、下記)。

参考(M5 時点、全 15 エフェクト既定、WSL2 / 24 論理コア、`preset: medium`・`crf: 18`、60 秒・22 クリップ): 1280×720 は `jobs=1` で 29.7 秒(ピークメモリ約 1GB。`reverse` のバッファを含む)、`jobs=4` で 11 秒、`jobs=12` で 9.7 秒。1920×1080 は `jobs=12` で 18 秒(ピークメモリ約 1.4GB)。frame 系 processor の 1 フレームあたりの時間は 720p で、`kaleidoscope` 14ms、`tile` 8ms、`mirror` 2ms、その他 1.5ms 以下。1080p では約 2 倍。Windows ネイティブでも同条件でほぼ同じ数値(README)。

参考(M1 時点、エフェクトなし、WSL2 / 24 論理コア、`preset: ultrafast`、1 クリップ 0.2 秒): 60 秒・300 クリップの生成に 3.9 秒。ffmpeg の起動回数は、この規模では問題にならなかった。Windows ネイティブでの同条件の数値は未測定(近い条件として、C5 の 5 分・431 クリップの実測が TESTING.md にある)。

## 16. 決定事項

1. 「反転」は幾何反転(`flip`)と色反転(`negate`)の両方を実装する。
2. BPM 解析は、numpy による自前の実装とする(librosa は精度が足りないため不採用。§4.3)。`--bpm` で手動指定できる。
3. 設定ファイルは YAML とする。
4. 音声が出力長より短い場合は、無音で埋めて警告する。
5. 出力長の未指定時は音声の長さを使う。
6. コマンド名は `mkaleido`、パッケージ名は `moviekaleidoscope` とする。
7. plan は常に出力の隣に保存する。
8. `tile` の「組み合わせ」は、`tile` 内の transform(`none` / `scroll` / `rotate` / `scroll+rotate`)で表現する。任意のエフェクト同士の重ね掛けは将来対応とする。
9. セグメント生成の進捗は、クリップ数ではなくフレーム数で報告する。
10. 全セグメントを BT.709 / limited range に正規化して、タグを明示する(§3.3)。
11. 未了だったもの(Windows ネイティブでの実行(性能・全テスト。GUI の見た目の確認を含む)、CI の実行)は、2026-11-16 までにすべて完了(TESTING.md)。
12. GUI は tkinter で作る(§17)。


## 17. GUI(第 2 段階)

### 17.1 方針

- core(`moviekaleidoscope.api`)の薄いラッパーとし、CLI と同じ設定の検証・同じ生成処理を使う。GUI だけに存在する規則は作らない。
- **tkinter** を使う。標準ライブラリなので追加の依存がなく、Windows・macOS・Linux で同じコードが動く(Windows の公式インストーラーの Python には含まれる)。見た目は素朴だが、配布の手軽さを優先する。Qt(PySide6)と Web UI は、依存・配布サイズ・保守の面で見送った。
- 起動は `mkaleido-gui`(Windows ではコンソールなしで起動する gui-script)または `python -m moviekaleidoscope.gui`。tkinter がない環境では、導入方法を示して終了コード 1 で終わる(コマンドライン版は tkinter なしで使える)。

### 17.2 構成

| モジュール | 役割 | 画面 |
|---|---|---|
| `gui/model.py` | フォームの内容(`GuiSettings`。すべて文字列で、空欄は「未設定」)と、`Config` への変換、設定ファイルの読み書き、前回設定の記憶 | 不要 |
| `gui/runner.py` | 1 つのジョブを別スレッドで実行し、進捗・ログ・結果をキューで返す(`JobRunner`)。生成 / plan のみ / plan から再生成のジョブ | 不要 |
| `gui/app.py` | ウィンドウ。モデルとランナーを呼ぶだけ | 必要 |

- 画面に依存しない部分(model、runner)は、画面なしで自動テストできる。
- `Config` を設定ファイルの形で書き出す `Config.to_file_dict()` を core に置く(`config_from_dict(cfg.to_file_dict()) == cfg`)。GUI の設定保存と、`--dump-config`(出力を設定ファイルとして読み込める)が使う。

### 17.3 画面

4 つのタブと、常に見える実行領域からなる。

| タブ | 内容 |
|---|---|
| 入力と出力 | 入力のリスト(ファイル・フォルダ。追加・削除)、サブフォルダを探すか、出力ファイル、上書きするか、長さ |
| 音楽とカット | 音声ファイル・開始位置・BPM(空欄で自動検出)、カット方式(自動 / 拍に合わせる / 固定 / ランダム)、方式ごとの長さ・拍数。使わない欄は無効になる |
| 見た目 | 使うエフェクトのチェック(15 種)、出力の幅・高さ・FPS・CRF・速さ(プリセット) |
| 詳細 | シード、並列数、ffmpeg の場所 |

実行領域: 「動画を作る」「構成(plan)だけ作る」「中止」、段階の表示と進捗バー、ログ、完了後の「出力のフォルダを開く」「動画を再生」。メニューに「設定を開く / 保存」「plan から動画を作り直す」「終了」。

### 17.4 動作の規則

- 実行前に、CLI と同じ検証(`validate_for_run`)を行う。問題があれば、フィールド名を含むメッセージをダイアログで示し、実行しない。上書きが必要なときは、GUI の「上書きする」を案内する。
- 実行中は、フォームとメニュー(終了以外)を無効にし、「中止」だけを有効にする。終了後に戻す。ジョブは 1 つずつ。
- 生成は別スレッドで動き、画面は固まらない。ジョブからの通知は、キューを介して画面側が 100ms ごとに取り込む(`poll_now()` は即座に取り込む)。1 つのイベントの処理に失敗しても、取り込みは止めない。
- 進捗バーは段階ごとの重み(入力検証 5%、BPM 解析 5%、計画 2%、セグメント生成 80%、連結 8%)で、全体として前へしか進まない。
- 失敗はダイアログで示し、ログにも残す。想定外の例外は、トレースバックをログに出す。中止は「中止しました」とログに残す。
- 終了時にジョブが動いていれば、確認してから中止し、終わるのを待つ。
- **設定の保存と読み込み**: 設定ファイルは CLI と同じ YAML。フォームにない項目(エフェクトの重み・パラメータ範囲、拡張子、plan の保存先、`beat_offset`、`bpm_range`、作業フォルダなど)は、読み込んだファイルのものを保持して、保存時に書き戻す。空欄にした項目は、読み込んだファイルの値が残らない。エフェクトのチェックを外したものは `exclude` として保存する(`enabled: all`)。
- **前回の設定の記憶**: 終了時と実行時に、ユーザーごとの場所(Windows: `%APPDATA%\MovieKaleidoscope`、それ以外: `~/.config/moviekaleidoscope`)に保存し、次の起動で復元する。「上書きする」は復元しない。壊れていても無視する。
- フォントは、日本語に対応した最初のもの(Yu Gothic UI、Meiryo UI、Hiragino Sans、Noto Sans CJK JP など)を明示して選ぶ。ログ欄の既定の等幅フォントは日本語を持たないことがあるため。

### 17.5 対象外(第 2 段階)

ドラッグ&ドロップ、動画のプレビュー、タイムラインや plan の編集、エフェクトの重み・パラメータ範囲の編集(設定ファイルで行う)、複数ジョブの同時実行。

### 17.6 テストと確認

- model と runner は画面なしで、実ファイルを使って検査する(進捗・ログの取り込み、失敗、中止、同時実行の拒否、ロギングの後始末、フィールドごとのエラーメッセージ、設定の往復、記憶と復元)。
- ウィンドウは、表示環境のもとで、プログラムから操作して検査する(フォームの往復、無効化、ボタン、ダイアログ、生成・失敗・中止・plan のみ・plan から再生成・設定の保存と読み込み・終了時の確認、進捗バーが前へしか進まないこと)。表示がない環境ではスキップし、Linux の CI は仮想ディスプレイ(xvfb)で実行する。
- 仮想ディスプレイのスクリーンショットで、各タブ・実行中・完了後の見た目を確認した。Windows ネイティブでの見た目と操作(表示倍率 125%/150%、日本語フォント、ダイアログ、コンソールが出ないこと、実行中のロックと中止)は、利用者が実機で確認して OK(2026-11-16。TESTING.md の C1)。
- **環境の注意**: Tk の `after` タイマーは壁時計に従う。WSL2 では壁時計が数十秒単位で後ろへ跳ぶことがあり、そのときは取り込みが跳んだ分だけ遅れる(ジョブ自体は止まらない)。テストは `poll_now()` で取り込み、タイマーに依存しない。
